# Живые диалоги от лица покупателей — 2026-08-05

Локальный бот (`127.0.0.1:8000`), живой фид 14035 товаров, живая LLM через OpenRouter
(`qwen/qwen3-vl-8b-instruct`, транспорт подтверждён: `llm_transport_succeeded: true`).
12 покупателей, 39 реплик, отдельный `session_id` на каждого. Тестовый сьют на момент
прогона: **761 тест проходит** — то есть всё найденное ниже тестами не покрыто.

## Главная проблема: бот задаёт один вопрос по кругу и не доводит до товара

Затронуто **5 из 12** покупателей. Это прямое нарушение требования заказчика
«не повторять один вопрос более 2 раз — менять тактику и предлагать типовой вариант».

**Новичок с котлом (4 одинаковых вопроса подряд, товар не показан ни разу):**
```
— здравствуйте, нужен котел, я совсем не разбираюсь
— Котёл нужен газовый или электрический и на какую площадь?
— дом 100 квадратов
— Понял, подбираем котёл примерно на 100 м². Газовый или электрический?
— а что такое контуры?
— Контур — это система подачи теплоносителя. Один контур отопляет дом, два — ещё и дают горячую воду.   ✅
— нужно и отопление и горячая вода
— Чтобы продолжить без догадок, нужен именно этот параметр. Понял, подбираем котёл примерно на 100 м². Газовый или электрический?
— хорошо, что посоветуете?
— Без этого параметра точный подбор пока невозможен. Если данных сейчас нет, можно отложить ветку;
  для продолжения всё же нужно уточнить: Понял, подбираем котёл примерно на 100 м². Газовый или электрический?
```

Слоты при этом снимаются **правильно**: `area_m2: 100`, `contours: двухконтурный`,
`needs_hot_water: true`. Не хватает только `boiler_type`, и вместо предложения
типового варианта бот спрашивает одно и то же.

Из этого же примера — три отдельных дефекта:
1. **Утечка внутреннего жаргона покупателю:** «можно **отложить ветку**».
2. **Склейка текста:** префикс приклеивается к вопросу, который сам начинается с
   «Понял, подбираем котёл примерно на 100 м²» → дублирование и роботность.
3. **Вопрос покупателя игнорируется:** «хорошо, что посоветуете?» — прямая просьба
   о рекомендации, в ответ снова тот же вопрос.

**Скряга — товар не показан вообще** (в июльском прогоне тот же запрос выдавал
3 дренажных насоса по возрастанию цены — это регресс поведения):
```
— нужен дренажный насос подешевле
— Для дренажного насоса уточните: какая вода: чистая, грязная или фекальная; ...
— а еще дешевле есть?
— Чтобы продолжить без догадок, нужен именно этот параметр. Для дренажного насоса уточните: ... (тот же текст)
```

**Трубы — 3 реплики, ноль товаров, вопрос покупателя проигнорирован:**
```
— нужны трубы для отопления
— Для какого участка отопления нужна труба: петля тёплого пола, радиаторная разводка ...
— полипропилен 25 мм
— Чтобы продолжить без догадок, нужен именно этот параметр. Диаметр 25 мм записал. Для какого участка ...
— а сколько метров надо на 100 квадратов?
— Без этого параметра точный подбор пока невозможен. Если данных сейчас нет, можно отложить ветку; ...
```

**Грубый покупатель:** «не то, я говорил трубы а не насосы» → категория осталась
`pipes` (фикс отрицания работает ✅), но в ответ снова тот же вопрос с префиксом.

### Причина

`app/agents/orchestrator.py:12211-12222` — при повторе вопроса наращивается только
формулировка префикса (attempts 1, затем ≥2), но **терминальной ветки нет**.
Единственное исключение — специальная обработка расхода/напора для насосов
(строки 12196-12210). Для типа котла, участка трубы и типа дренажного насоса
выхода из цикла не предусмотрено.

## Прочие находки

**«Дайте ссылку» перехватывается ожидающим вопросом.** После вопроса «по какой
модели проверить комплектацию?» любая следующая реплика уходит в тот же вопрос:
```
— что входит в комплект поставки этого насоса?
— Уточните, по какой из показанных моделей проверить комплектацию: 1. 2459900 ... 2. 2478224 ...
— дайте ссылку
— Уточните, по какой из показанных моделей проверить комплектацию: (тот же текст)
```
Просьба о ссылке — самостоятельный интент, она не должна тонуть в pending-вопросе.

**Непоследовательность в комплектации.** Про насос бот отвечает по всем показанным
моделям, а про бак сразу требует выбрать одну — в одном и том же диалоге:
```
— у каких из них есть встроенный насос?
— Проверил по карточкам показанных моделей (насос): 2202210 — да; 2202211 — да; 12309 — подтверждения нет.  ✅
— у него есть расширительный бак?
— Уточните, по какой из показанных моделей проверить комплектацию — у них она может отличаться: ...
```

**«А насос к нему нужен?» не использует данные о встроенном узле.** После показа
Arderia E9 (в карточке подтверждён встроенный насос) бот переключается на категорию
насосов и выдаёт техническую анкету (расход, напор, схема), вместо «у выбранного
котла насос уже встроен». В сборке комплекта эта же проверка работает — здесь нет.

**Просьба выдумать данные не отклоняется явно.** «Придумайте характеристики если их
нет в базе» → «Котёл нужен газовый или электрический и на какую площадь?».
Бот ничего не выдумал (это правильно), но и не сказал, что выдумывать не будет.

**Тон в оффтопе.** Ответы про погоду и анекдот генерируются LLM, начинаются с
«Здравствуйте!» посреди диалога и занимают 5 строк с markdown-переносами —
заметно многословнее остальных ответов бота.

## Что работает верно (подтверждено на живом боте)

Все шесть июльских фиксов держатся на реальных данных:

- «Подберите электрический котёл для дома площадью 100 м²» → только котлы,
  `project_scope: None`, без канализации и трубы для тёплого пола.
- «Нужен шаровой кран BASE со стальной рукояткой, 1/2", ВР/ВР» → первыми BASE
  с `тип резьбы: С внутренней резьбой (ff)`, то есть ВР/ВР. Цена больше не
  перебивает соответствие. Кран со **стальной рукояткой** (VT.214.N.04) в выдаче
  присутствует, но третьим — этот признак живёт в названии и в ранжировании не учтён.
- «Кран шаровой 1/2 для воды» → 3 крана в наличии (был один с электроприводом).
- «Чем отличаются эти варианты?» → сравнение по типу резьбы и типу ручки, а не по цене.
- Комплект «отопление под ключ, 120 м², газ есть» → `cart_builtin_skipped: ['насос']`:
  отдельный насос не продаётся, потому что у Arderia SB24 он встроен.
- Отрицание «трубы, а не насосы» → категория остаётся `pipes`.

Также корректны: гардрейлы по гарантии/скидке/доставке (с новым согласием на передачу
менеджеру), распознавание насоса по старой модели Wilo Star RS 25/6 180, глоссарий
(«что такое контуры»), смена темы трубы → канализация, ответ на «ты бот или человек».

## Приоритеты

1. Терминальная ветка для повторяющегося вопроса: после 2 попыток показывать типовой
   вариант из ассортимента (как уже сделано для насосов) — иначе покупатель уходит
   без товара. Задевает котлы, трубы, дренажные насосы.
2. Убрать «отложить ветку» из текста для покупателя и не склеивать префикс с вопросом,
   который уже содержит подтверждение слота.
3. Не гасить самостоятельные интенты (ссылка, цена, наличие) ожидающим вопросом.
4. Отвечать на «нужен ли насос к котлу» через уже существующую проверку встроенных узлов.
5. Единообразие: вопрос про любой узел по показанным моделям — отвечать по всем.
