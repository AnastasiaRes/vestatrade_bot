# Capability-aware V2 / Legacy cutover

Дата: 2026-08-31

Ветка: `qa/live-evaluation-and-fixes-2026-08-22`

Исходный HEAD: `3b4b3acd97bd1087b29e7ef1816541f4a08f2503`

## Результат

В существующий cutover добавлен версионированный слой владения capability.
Он не создаёт второго router или dialogue state: V2 по-прежнему строит
кандидат без видимого коммита, один детерминированный resolver выбирает
владельца, а существующая cutover policy разрешает выполнить только один
ответный контур.

Текущий безопасный allowlist Legacy:

- структурированный список позиций;
- бытовое описание инженерной проблемы;
- подтверждённые инженерные нормы;
- коммерческие и сервисные темы, которые ещё не готовы в V2;
- точный small talk без товарного содержания.

V2 остаётся владельцем готовых каталоговых действий, ProductFact, Selection,
Compare, Calculate, Compatibility, source-backed OfferFact и действительно
проверенных коммерческих фактов. Гидравлический расчёт системы не передаётся
старому генератору: его обслуживает существующая безопасная V2-граница.

Если public-primary ход не покрыт ни одним разрешённым исполнителем, система
возвращает типизированный V2 `capability_not_ready`. Неизвестный запрос больше
не является разрешением запустить широкий Legacy-ответ.

## Состояние и один владелец

- V2-кандидат строится до выбора владельца, но не коммитится заранее.
- При выборе Legacy конкурирующий V2 state не сохраняется даже как будущая
  видимая conversational state.
- При выборе V2 состояние и ответ коммитятся атомарно существующим cutover.
- Shadow не меняет видимый ответ или Legacy-state.
- Protected Preview сохраняет существующий валидированный мост карточек для
  миграционной диагностики; public-primary не импортирует непроверенный текст.

Для продолжения статуса заказа используется минимальная проекция уже
существующей Legacy-сессии — только имя активной темы, без контакта или номера
заказа. Это не второе состояние. Короткое `Номер 148237` считается номером
заказа только после доказанного вопроса Legacy о заказе. Вне этого контекста
пять цифр остаются неоднозначными и не получают глобального commerce-смысла.

## Дополнительный найденный шов

Фраза `Покажите цену и наличие Arderia E9` сначала не доходила до строгого
OfferFact, хотя каталог правильно разрешал модель в SKU `2202210`. Причиной
были формы слов `цену` и `наличие`, отсутствовавшие в детерминированном
детекторе. Детектор расширен на русские словоформы; SKU-resolver, feed и
ranking не менялись.

## Живой прогон

Один ограниченный прогон выполнен через настоящий `/chat` в public-primary
конфигурации с реальной OpenRouter LLM, feed100 и текущими паспортами. Полные
матрицы не повторялись.

| Ход | Владелец | Результат |
|---|---|---|
| `Где мой заказ?` | Legacy | Честная граница без CRM; запрошены номер заказа и контакт. |
| `Номер 148237` | Legacy continuation | Номер сохранён; повторно не запрашивается, остался только контакт. |
| `Теперь покажите цену и наличие Arderia E9` | V2 | `2202210`, `35365 ₽`, статус наличия и прямой URL из feed. |
| `Здравствуйте!` → `Покажите цену и наличие Arderia E9` | Legacy → V2 | Small talk не закрепил сессию за Legacy; товарный ход вернулся в V2. |
| список PPR-позиций | Legacy | Один Legacy-ответ, без V2-коммита. |
| запах из душевого слива | Legacy | Предметная диагностика вместо случайной карточки. |
| уклон наружной канализации 110 мм | Legacy | Детерминированная норма. |
| неизвестный общий запрос | V2 boundary | Fail-closed, широкий Legacy не запускался. |

Телеметрия финальной цепочки:

- `legacy.commerce_topic`, `response_owner=legacy`, V2 commit отсутствует;
- `legacy.commerce_topic` + `capability_owner_legacy_continuation`, commit
  отсутствует;
- `v2.catalogue_turn`, `response_owner=v2`, атомарный commit выполнен.

## Ограничения и следующий этап

Capability-aware fallback сейчас намеренно узкий. Нельзя расширять его до
правила «если V2 не ответила — всегда спросить Legacy»: это снова разрешит
выдумки и смешение состояний.

Следующий перенос следует делать по тому же шаблону: заранее выделить одну
детерминированную Legacy-capability, описать её typed outcome и gate, проверить
паритет, затем перевести владельца в V2. Кандидаты: explanation/terms,
commercial handoff и расширение списков позиций. Инженерные расчёты и
неподтверждённые рекомендации не входят в автоматический fallback.

Коммит, push и изменение rollout-флагов в рамках этапа не выполнялись.
