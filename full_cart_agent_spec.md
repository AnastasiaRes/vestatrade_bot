# Агент-комплектатор полной корзины

## Результат живого теста текущего бота

Сценарий проверен 27 июля 2026 на https://bot-api-vestatrade.ru/.

Исходная задача:

- двухэтажный дом 140 м²;
- котёл и 10 радиаторов уже куплены;
- водяной тёплый пол 35 м², 5 петель;
- две зоны управления;
- бюджет на обвязку и автоматику до 120 000 рублей;
- требуется полная предварительная корзина с количеством, ценами, назначением и итогом.

Боту дополнительно передали:

- котёл Arderia E12, артикул 2202211;
- закрытая двухтрубная система;
- теплоноситель — вода;
- 10 стальных радиаторов с нижним подключением 1/2";
- 5 петель тёплого пола примерно по 60 м, труба 16×2;
- радиаторы 65–70 °C, тёплый пол 35–40 °C;
- требуется безопасный подмес;
- неизвестный метраж магистралей нельзя угадывать.

### Что произошло

1. Первый вопрос был разумным: бот запросил модель котла и тип системы.
2. После получения модели и точного артикула бот заявил: «нет артикула/модели».
3. Вместо корзины он вывел пользователю внутреннюю сводку с техническим полем `key_requirements`.
4. Пользователь явно написал: «Не передавайте менеджеру». Бот проигнорировал запрет.
5. Бот дважды сообщил, что передал вопрос менеджеру и сохранил историю диалога.
6. Даже после просьбы подобрать только один раздел — комплект тёплого пола — бот снова повторил передачу менеджеру.
7. Ни одного товара, количества, расчёта строки или общего итога не появилось.

Оценка текущего сценария: **1/10, не пройден**.

Новые критические дефекты:

- потеря точного артикула в пределах соседнего сообщения;
- раскрытие внутреннего формата маршрутизации;
- игнорирование прямого запрета на передачу менеджеру;
- вероятное создание повторных обращений;
- цикл handoff вместо продолжения консультации.

Контактные данные в тесте не передавались. Необходимо проверить бэкенд на тестовые или дублирующиеся обращения, созданные этим диалогом.

## Назначение нового агента

Агент-комплектатор должен превращать сложную бытовую задачу в проверяемую предварительную корзину:

1. Удерживать все известные параметры проекта.
2. Самостоятельно выявлять недостающие сведения.
3. Делить систему на подсистемы.
4. Подбирать товары из каталога.
5. Рассчитывать количества и стоимость.
6. Проверять совместимость и отсутствие дублей.
7. Объяснять назначение каждой позиции.
8. Отделять подтверждённое от условного и требующего расчёта.
9. Не подменять инженерный проект и не давать опасных обещаний.

## Предлагаемая архитектура

### 1. Router

Отдельный intent:

`complex_basket`

Признаки:

- «собрать всё»;
- «полная корзина»;
- «под ключ»;
- несколько товарных категорий;
- расчёт количества;
- совместимость существующего оборудования;
- общий бюджет;
- задача ремонта, отопления, водоснабжения или санузла целиком.

После выбора этого intent нельзя автоматически возвращаться к простому поиску одного товара или к handoff.

### 2. Project State

Контекст нужно хранить структурированно, а не восстанавливать из последнего сообщения.

```json
{
  "project": {
    "type": "heating_system",
    "area_m2": 140,
    "floors": 2,
    "budget_rub": 120000
  },
  "heat_source": {
    "existing": true,
    "model": "Arderia E12",
    "sku": "2202211",
    "verified_features": [],
    "unverified_features": [
      "встроенный насос",
      "расширительный бак",
      "группа безопасности"
    ]
  },
  "radiators": {
    "existing": true,
    "count": 10,
    "material": "steel",
    "connection": "bottom 1/2",
    "supply_temperature_c": "65-70"
  },
  "floor_heating": {
    "area_m2": 35,
    "loop_count": 5,
    "loop_lengths_m": [60, 60, 60, 60, 60],
    "pipe": "16x2 oxygen barrier",
    "zone_count": 2,
    "target_temperature_c": "35-40"
  },
  "system": {
    "type": "closed",
    "layout": "two-pipe",
    "fluid": "water"
  },
  "hard_constraints": {
    "do_not_guess_lengths": true,
    "avoid_duplicates": true,
    "require_safe_mixing": true

  "unknowns": [
    "main_pipe_routes",

    "requested_by_user": false,

```

Каждая новая реплика обновляет это состояние. Явная коррекция пользователя имеет приоритет над предыдущим выводом классификатора.

### 3. Catalog tools

Минимально нужны операции:

- поиск точного товара по артикулу;
- получение комплектации существующего оборудования;
- поиск по категории и обязательным фильтрам;
- получение текущей цены, остатка и ссылки;
- проверка характеристик и совместимых аксессуаров;
- расчёт суммы по количеству.

Каждый выбранный товар должен пройти финальную проверку всех жёстких условий перед показом пользователю.

### 4. Compatibility layer

Отдельные правила должны проверять:

- температуру и давление;
- диаметр и тип соединения;
- материал и допустимый теплоноситель;
- напряжение, NC/NO и тип контакта автоматики;
- число контуров, приводов и зон;
- наличие компонентов в комплекте;
- необходимость смешения высоко- и низкотемпературных контуров;
- допустимость насоса по расчётному расходу и сопротивлению;
- бюджет.

### 5. Basket calculator

Каждая строка:

```json
{
  "subsystem": "floor_heating",
  "sku": "…",
  "name": "…",
  "quantity": 5,
  "unit_price_rub": 0,
  "line_total_rub": 0,
  "purpose": "…",
  "compatibility": "confirmed | conditional | not_checked",
  "included_in_other_product": false,
  "stock": "…",
  "url": "…"
}
```

Расчёты:

- `line_total = quantity × unit_price`;
- итог по каждой подсистеме;
- общий итог;
- остаток или превышение бюджета;
- отдельная сумма условных позиций;
- монтаж и доставка не смешиваются с ценой товаров.

## Диалоговый процесс

### Шаг 1. Зафиксировать задачу

Коротко повторить только распознанные факты:

> Понял: дом 140 м², 10 существующих радиаторов, тёплый пол 35 м²/5 петель, котёл уже есть, бюджет 120 000 рублей. Собираем предварительную корзину обвязки и автоматики.

Не копировать весь пользовательский текст.

### Шаг 2. Задать недостающие вопросы

Не больше 3–5 вопросов за одно сообщение:

1. Модель и артикул котла.
2. Тип системы и теплоноситель.
3. Схема подключения и фактические размеры.
4. Температуры радиаторов и тёплого пола.
5. Число зон и требования к автоматике.

После получения ответа нельзя спрашивать те же данные повторно.

### Шаг 3. Построить каркас корзины

До выбора SKU показать подсистемы:

1. Радиаторный контур.
2. Тёплый пол.
3. Общесистемная обвязка и защита.
4. Автоматика.
5. Трубы, фитинги и монтажные материалы.

Для каждой позиции поставить статус:

- подтверждена;
- подобрать;
- зависит от проекта;
- уже входит в существующее оборудование;
- опциональна.

### Шаг 4. Проверить существующее оборудование

До добавления насоса, бака или группы безопасности проверить карточку и документацию котла.

Если комплектация не подтверждена:

> Не добавляю второй насос/бак/группу безопасности как обязательные. Сначала проверяем паспорт и гидравлический расчёт.

### Шаг 5. Подбирать по одной подсистеме

Это уменьшит вероятность смешения характеристик:

1. Коллектор и смешение тёплого пола.
2. Автоматика.
3. Радиаторная арматура.
4. Защита и сервисная обвязка.
5. Трубы и монтажные материалы.

После каждого раздела показать промежуточную сумму и нерешённые вопросы.

### Шаг 6. Финальная проверка

Перед ответом:

- все ли 10 радиаторов учтены;
- ровно ли 5 контуров;
- 5 приводов и 2 термостата не перепутаны;
- нет ли прямой подачи 65–70 °C в пол;
- нет ли дублей встроенного оборудования;
- нет ли товаров выше бюджета без явной маркировки;
- все ли количества имеют источник расчёта;
- неизвестные метражи остались неизвестными;
- итог сходится арифметически.

### Шаг 7. Handoff

Передача менеджеру допускается только после явного согласия:

> Я могу передать менеджеру эту предварительную корзину и историю диалога. Передавать?

После согласия:

1. Показать, какие данные будут отправлены.
2. Получить контакт и согласие на обработку.
3. Вызвать интеграцию один раз.
4. Сообщить об успехе только после ответа API.
5. Показать номер обращения.

Если API не вернул ID:

> Не удалось подтвердить создание обращения. Я не буду говорить, что оно передано.

Фраза «не передавайте менеджеру» должна жёстко блокировать handoff.

## Минимальная предварительная корзина для тестового сценария

### Радиаторный контур

- 10 комплектов подключения с термостатическим и запорным/балансировочным элементом — после проверки фактической комплектации радиаторов.
- 10 термоголовок.
- Воздухоотводчики, заглушки и крепления — только если не входят в радиаторы.
- Подающие и обратные трубы, теплоизоляция, фитинги и крепления — количество по плану трасс.
- Балансировка этажей или ветвей — по подтверждённой схеме.

### Тёплый пол

- 1 коллектор ровно на 5 контуров с расходомерами.
- 1 безопасный смесительный узел с ограничением температуры.
- Насос смесительного узла — только после проверки расхода и сопротивления либо как часть подтверждённого готового модуля.
- 5 приводов.
- 2 комнатных термостата.
- 1 совместимый коммутационный центр.
- Труба 16×2 с кислородным барьером: заданные 300 м плюс обоснованный монтажный запас, если 60 м — длина каждой петли с подводами.
- Коллекторный шкаф, краны, заполнение/слив и воздухоотвод — с учётом комплектации коллектора.
- Теплоизоляция основания, демпферная лента, крепления и гильзы — по площади и плану.

### Общесистемная часть

- Грязевик или магнитный фильтр на обратке.
- Сервисная запорная и сливная арматура.
- Дополнительный расширительный бак — только по расчёту общего объёма системы.
- Дополнительная группа безопасности — только если она не входит в котёл или нужна по подтверждённой схеме.
- Дополнительный системный насос, гидроразделитель или буфер — только по гидравлическому расчёту.

## Приёмочные тесты

### Контекст

- После сообщения с артикулом 2202211 бот больше не спрашивает артикул.
- После «котёл уже куплен» он не добавляет новый котёл в корзину.
- После «5 петель, 2 зоны» предлагает 5 приводов и 2 термостата, а не наоборот.

### Ограничения

- Не показывает товар выше бюджета как подходящий.
- Не выдумывает метраж магистралей без плана.
- Не добавляет второй насос, бак или группу безопасности без проверки.

### Безопасность

- Не подаёт 65–70 °C напрямую в тёплый пол.
- Не выбирает насос «по площади дома».
- Не обещает, что комплект точно заработает без расчёта и проверки.

### Handoff

- «Не передавайте менеджеру» гарантированно не создаёт обращение.
- Повторный запрос не создаёт дубликат заявки.
- Успешная передача всегда сопровождается `ticket_id`.

### Вывод

- Есть товары, количества, цены строк и арифметически правильный итог.
- Есть разделы «подтверждено», «условно» и «требует расчёта».
- В ответе нет `key_requirements`, JSON, внутренних маршрутов и полной копии истории.
